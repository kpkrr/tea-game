# PROTOTYPE — web-spike

**Статус:** concluded (2026-09-30)

> Одноразовый код. Не переносить в `src/`. Результаты вписываются в ADR, после
> чего прототип архивируется.

## Вопрос

Выдерживает ли web-сборка Godot 4.7.2 (single-thread, Compatibility/WebGL2)
решения ADR-0001/0002/0003/0005/0006/0007 на реальном телефоне: размер и время
запуска, пауза через `JavaScriptBridge`, сохранение в `localStorage` после
закрытия вкладки, задержка тапа, запекание NavMesh, порядок отрисовки спрайтов
(depth prepass на мобильных GPU), `scaling_3d_scale`, fps/draw calls при 75
инстансах, работает ли `Engine.max_fps`, читаемость цены на 9:20.

## Критерии успеха (из ADR)

- Загрузка ≤ 13,5 МБ сжатыми; холодный TTI ≤ 20 с при 10 Мбит/с; тёплый ≤ 6 с (ADR-0007).
- Пауза: callback видимости приходит, первый кадр после возврата не несёт скрытое время (ADR-0003).
- `localStorage` переживает закрытие вкладки (ADR-0005).
- NavMesh: запекание ≤ 100 мс, все точки достижимы (ADR-0006).
- 30 fps пол на слабом Android при 75 инстансах (ADR-0007).

## Запуск

```
# сборка (после правок spike.gd)
/Applications/Godot.app/Contents/MacOS/Godot --headless --path prototypes/web-spike --export-release Web build/index.html
cp prototypes/web-spike/shell/spike_shell.js prototypes/web-spike/build/

# сервер для телефона в той же Wi-Fi
python3 prototypes/web-spike/server.py   # HTTPS :8443, самоподписанный сертификат (Godot требует secure context)
```

Телефон открывает `https://<IP Mac>:8443` (предупреждение о сертификате — «всё равно перейти») и проходит 7 шагов на экране.
Отчёты падают в `results/<session>.jsonl`.

Отличия от настоящей игры: текстуры процедурные (время их генерации вычитается,
поле `texgen_ms_spike_only`), `.pck` почти пустой (≈ 30 КБ против бюджета 3 МБ).
Холодный TTI по Wi-Fi быстрее, чем по 10 Мбит/с: сетевая часть пересчитывается
из размеров файлов.
