## Overview

Tea Rush — одна кухня в портрете, одна рука, один жест. Почти всё
взаимодействие происходит **в мире**, а не в меню: игрок тапает станции,
гостей и пол, а состояние читает по объектам (чашка, чайник, касса, кольцо над
гостем). Экранный UI сведён к одной строке полосы (счёт, страйки, кнопки паузы и
звука) и двум модальным оверлеям (пауза и итоги). Вне партии — короткий поток
экранов (главное меню, How to Play, Settings, Records; `design/ux/game-flow.md`)
из обычных кнопок и переключателей. Поэтому библиотека короткая и почти целиком
состоит из паттернов «мир как интерфейс».

Паттерны извлечены из GDD и ADR; P14–P16 добавлены HUD-спекой
(`design/ux/hud.md`, 2026-09-30); P17–P20 — спекой потока экранов
(`design/ux/game-flow.md`, 2026-10-01). Весь текст, видимый игроку, — только на
английском (решение владельца F3, 2026-10-01). Каждый новый спек (`/ux-design results-overlay`
и далее) обязан ссылаться на паттерны отсюда по имени, а не изобретать свои.

**Сквозные правила** (действуют во всех паттернах):

- **Единица размеров — dp** эталонного канваса 360×640 (ADR-0002). Цели касания
  ≥ 48 dp, прощающий радиус выбора — 28 dp.
- **Один жест в игре.** В кухне и на иконках полосы — только press одним пальцем
  или левой кнопкой мыши: без удержаний, свайпов, двойных тапов и мультитача.
  Отпускание и drag игнорируются (TR-control-018). **Текстовые кнопки оверлеев и
  меню** (P17) срабатывают по release внутри кнопки — вне игрового темпа скорость
  не нужна, а release позволяет «сорваться» пальцем; свайп — только листание
  карточек How to Play. Клавиатура работает только на экранных кнопках (P4, P14,
  P17, P18, P19) и на Escape (пауза / Resume в партии, P15; «назад» на под-панелях
  паузы и в меню); сам игровой процесс — только тап/клик
  (`accessibility-requirements.md` — Known Limitations).
- **Мышь на ПК.** Над интерактивным элементом (кнопки P4/P14/P17, строка P18, цель P1) курсор —
  «рука» (`CURSOR_POINTING_HAND`). Hover-состояние — только от реальной мыши;
  на тач-устройствах hover не показывается и не «залипает».
- **Красный и зелёный никогда не кодируют состояние** — эти цвета заняты шагами
  рецепта (кипяток, зелёный лист). Состояние передаётся светлотой,
  насыщенностью, иконкой, силуэтом и движением.
- **Сначала форма, цвет вспомогательный.** Всё, что различается цветом,
  различается и формой (`accessibility-requirements.md` — Color-as-Only-Indicator Audit).
- **Звук никогда не единственный носитель.** В каждом паттерне есть визуальный
  сигнал; звук только дублирует его (Sound Standards).
- **Два вида времени.** Всё, что должно замирать на паузе, идёт от
  `GameClock.sim_dt`, а оверлей итогов — от `ui_dt` (ADR-0003 §6). Запрет на
  `Tween`, `Timer` и автоплей `AnimationPlayer` относится **только к эффектам в
  игровом времени** внутри движка; HTML-оболочка (P13) живёт вне движка и
  этим правилом не покрывается.
- **Reduced motion.** Флаг читается через `PlatformBridge.prefers_reduced_motion()`
  при старте и обновляется по сигналу `reduced_motion_changed(enabled)`
  (ADR-0001; оболочка берёт его из `matchMedia('(prefers-reduced-motion: reduce)')`).
  Потребители — HUD и мировые оверлеи; пульсы и дуги заменяются статичными
  вариантами (Animation Standards). Движение персонажей остаётся.
- **Бюджет кадра.** Все варианты (обычный, reduced motion, фоточувствительность)
  укладываются в строку ADR-0007 «Presentation scripts» (0,80 мс avg / 1,50 мс p99)
  и потолок draw calls.

## Standard Control Patterns

Каждый стандартный контрол либо сводится к паттерну из каталога, либо не
используется в MVP. Новый контрол в спеке экрана — только через добавление
строки сюда.

| Контрол | Статус в MVP | Паттерн / причина |
|---|---|---|
| Кнопка — основная | Используется | P17 primary (Play, Start shift, Resume, Play Again, End shift); на итогах дополнительно grace P4 |
| Кнопка — вторичная / иконка | Используется | P17 secondary / текстовая (Records, Settings, How to Play, Main Menu, Share, Menu, Cancel, Skip, Done); P14 (пауза, звук в полосе HUD; Back ← в разделах) |
| Кнопка — опасная | Используется | End shift — только внутри P19, никогда не в фокусе по умолчанию |
| Toggle | Используется | P14: «без звука» в полосе (`settings.muted`); P18: Music / Sound effects / Vibration в Settings (`settings.*_on`) |
| Slider | Не используется | Громкость — переключателями вкл/выкл (P18); ползунки отклонены владельцем 2026-10-01 |
| Dropdown | Не используется | Выбора из списка нет (язык — только английский) |
| List | Используется (неинтерактивный) | Records: «Last shifts» — до 5 строк текста; лидерборд — Vertical Slice |
| Grid | Не используется | Инвентаря и выбора предметов нет; 7 слотов — объекты мира (P1) |
| Modal | Используется | P12 (оверлей итогов), P15 (пауза), P19 (End shift?), слой «Rotate your phone» + P5 (маршрутизация) |
| Dialog подтверждения | Используется | P19 — End shift? (выход из партии в меню) |
| Toast / уведомление | Используется | P20 — плашки «Till full!», NEW BEST!, «Image saved, text copied» (фолбэк Share); остальные события — на объекте (P9) или числом (P10) |
| Tooltip | Не используется | Обучение — карточки How to Play (`game-flow.md`) и встроенный разгон; hover есть не у всех игроков |
| Progress bar | Используется как паттерн | Загрузка — P13; терпение — P8 (кольцо); касса и чайник — P9 (заполнение на предмете) |
| Input field | Не используется | Ввода текста нет (имя для лидерборда — VS) |
| Tab bar | Не используется | Поток плоский: меню → раздел, Back (`game-flow.md`) |
| Scroll | Используется точечно | Только панель About (лицензии); остальное помещается в портретный кадр (ADR-0002) |

## Animation Standards

**Правило разделения (art-bible §7.5).** Утрированная мультяшная анимация A3 —
squash & stretch, замах, перелёт, smear — **только персонажам** (бариста, гости);
reduced motion её не отключает. Анимация UI берёт параметры **только из этой
таблицы**: вход 120–180 мс ease-out-back с перелётом ≤ 1,1, выход 100 мс ease-in,
штампы — масштаб 1,3 → 1,0; smear и перелёт к тексту не применяются. Каждое новое
движение UI (зажигание неона в меню, лучи кассы, штамп) обязано иметь вариант для
reduced motion; мерцание неона ≤ 3 Гц и при reduced motion отсутствует.

**Типографика (art-bible §7.2).** Текст ≥ 14 dp (цена на жетоне 12 dp — единственное
исключение); display-шрифт Fredoka — только от 20 dp; **обводка у текста — только от
18 dp**; меняющиеся числа — Nunito с табличными цифрами (`tnum`); текст на пергаменте —
только Ink, Mint Ink, Gold Ink.

Длительности — ориентиры GDD («~»); точные значения — данные, настраиваются.
Источник времени: `sim_dt` — замирает на паузе; `ui_dt` — идёт при открытом
оверлее итогов, стоит при скрытой вкладке и на пользовательской паузе (ADR-0003 §6,
Amendment 2026-09-30); `CSS` — оболочка вне движка.

| Событие | Паттерн | Длительность | Источник времени | Reduced motion |
|---|---|---|---|---|
| Кольцо точки назначения — появление и угасание | P6 | ~300 мс + ~300 мс (или до прибытия) | `sim_dt` | Появляется и исчезает без пульса |
| Контур выбранной цели | P6 | до прибытия / перенаправления | `sim_dt` | Без изменений (статичен) |
| Пульс кольца терпения: warn | P8 | ~0,5 Гц | `sim_dt` | Нет пульса; иконка уровня |
| Пульс кольца терпения: urgent | P8 | ≤ 2 Гц | `sim_dt` | Нет пульса; иконка + поза «злость» |
| Снятие кольца / бирки при Served, Leaving | P7, P8 | мгновенно | — | То же |
| Вспышка совпадения чашки | P9 | одиночная, короткая | `sim_dt` | Остаётся (не цикл) |

| Переход меню ↔ раздел | P17 | cross-fade 200 мс | реальное время UI (вне партии) | Мгновенно |
| Меню → партия, итоги → меню | P17 | fade 300 мс | реальное время UI | Мгновенно |
| Нажатие кнопки меню | P17 | темнее + сдвиг 2 dp на press, действие на release | реальное время UI (на паузе — без анимации, `ui_dt = 0`) | Только темнее |
| Карточки How to Play | — | сдвиг 200 мс | реальное время UI | Мгновенно |
| «Вдыхание» кнопки при включении | P4 | одиночное | `ui_dt` | Нет |
| Переход загрузка → игра | P13 | CSS cross-fade | `CSS` (вне движка) | Мгновенная смена без fade |

Общие ограничения: ничего не мигает чаще 3 раз в секунду с перепадом яркости
(в сумме по экрану, даже при четырёх кольцах urgent); полноэкранных вспышек и
тряски экрана нет; hit-stop не используется.

## Sound Standards

Звуковая система — Vertical Slice (Audio & Juice Feedback); до неё звуки из
GDD — заглушки или отсутствуют. Правило действует уже сейчас: каждая строка
имеет визуальный дубль, и партия проходится без звука.

| Событие | Звук | Визуальный дубль |
|---|---|---|
| Тап по полу | Нет (утомляет в хаосе) | P6 кольцо |
| Тап по станции / гостю | Тихий «тик» — опционально (Open Question) | P6 контур |
| Отказ станции | У владельца (Brewing), не определён | P9 сигнал отказа |
| Чайник READY | Сигнал готовности | P9 янтарное свечение крышки + пар |
| Порча чашки | Глухой, без зуммера | P7 крестик + обесцвеченный ряд, мутная жидкость |
| Served → монеты / очки | Звон на `coins_added` + звук очков | P10 два попапа (иконка, цвет, направление) |
| Излишек при полной кассе | Глухой короткий «тук», без звона | P10 отскок монетки |
| Касса полна | Акцент «потолок» | P9 заполнение на кассе |
| Уход гостя (Leaving) | Негативный, не тревожный | P11 погасший страйк + поза и иконка гостя |
| Новый рекорд | Тёплый акцент | P12 отдельный акцент в оверлее |
| Нажатие Play Again | Нет (действие мгновенно видно) | P4 pressed + старт партии |
| Нажатие кнопки меню / переключателя | Тихий клик (если Sound effects вкл; спек Audio & Juice) | P17 / P18 pressed, смена ON / OFF |
| Касса полна посреди партии | Звон «касса полна» | P20 плашка + P9 касса |
| NEW BEST! в партии | Короткий стингер «рекорд» | P20 попап + золотой счёт |
| Последний страйк | Тихий слой «сердцебиение» (шина SFX) до конца партии | P20 виньетка + пульс иконки P11 |
| Тап по полосе / letterbox | Нет | — (намеренно нет реакции, P5) |
| Нажатие «пауза» / «звук» | Нет (иначе звук сообщал бы о собственном отключении) | P14 смена иконки; P15 оверлей |
| Музыка (одна зацикленная дорожка) | С первого жеста игрока (любое нажатие в меню); пауза потока на паузе и скрытой вкладке (возобновление с той же позиции); в `MatchEnd` — low-pass, не пауза (`hud.md` Музыка); `settings.muted` глушит SFX и музыку | Нет — музыка не несёт информации; кнопка звука показывает состояние формой (P14) |

## Patterns

Состояния в каждом паттерне: default, hover, focus, pressed, disabled; для
неинтерактивных паттернов — «N/A» с причиной.

### P1. World Tap Target

**Category**: Input · **Used In**: станции (7 видов), слоты (7), гости в Approaching/Waiting

**Description**: Игрок тапает объект кухни, бариста идёт к его точке
взаимодействия и выполняет действие. Выбор прощающий: в наклонной 2.5D-камере
точно попасть в маленький спрайт трудно, поэтому ближайший pick-якорь в
радиусе 28 dp выигрывает, даже если палец промахнулся мимо иконки.

**Specification**:
- Разрешение тапа (ADR-0006): вне `kitchen_rect` → ничего; ближайший pick-якорь
  (иконка станции / жетон гостя) ≤ 28 dp → эта цель; иначе луч по AABB
  станций, столешниц, стен, кассы и гостей; иначе плоскость пола (P2).
- Ничья по расстоянию: станция раньше гостя, потом меньший стабильный ID.
- Валидность спрашивается у владельца цели до выхода (Player Control Rule 4).
- **Отклонённый тап**: бариста не идёт, прежняя цель и путь сохраняются, контур
  P6 не показывается. Сигнал отказа рисует владелец (≤ 50 мс): Brewing даёт его
  только для недопустимого шага на станции ингредиента (AC-2.4) — это P9. Для
  остальных отказов (пустые руки у листа, занятый чайник, вторая чашка) —
  **намеренно нет обратной связи**: владельцы её не задают, а сигнал на каждый
  «пустой» тап шумит в хаосе и не несёт нового — состояние рук и чайника уже
  видно на предметах.
- Подтверждение — P6, в том же кадре, что и смена цели (TR-hud-021).
- На месте: действие мгновенное или WAIT (чайник заваривает) — ответ владельца.

**When to Use**: любой объект кухни, с которым бариста что-то делает.
**When NOT to Use**: элементы экранных полос и оверлея — это P4/P5; декор без действия — такие объекты не получают pick-якорь и для тапа считаются полом.

**States**: default — объект без выделения; hover (только мышь) — курсор «рука» над
целью, в которую попал бы клик; визуальной подсветки нет, чтобы не спутать с
контуром выбора P6; focus — N/A (клавиатура в игре не поддерживается); pressed —
это принятие цели, показывается P6; disabled — N/A (недоступность
выясняется только на тап — см. «Отклонённый тап»).

**Accessibility**: не требует точности (28 dp); одна рука; без цвета; только тап/клик
(Known Limitations).

**Implementation notes**: hover-курсор считается тем же резолвером ADR-0006 не чаще
раза за кадр по последнему `InputEventMouseMotion`; для эмулированных касаний
(`DEVICE_ID_EMULATION`) курсор не меняется. Звук действия принадлежит владельцу.
**Reference**: `player-control-barista-movement.md` Rules 1–5; ADR-0006 Decision 5–7.

### P3. Tap Redirect

**Category**: Input · **Used In**: весь ввод в кухне

**Description**: Очереди действий нет. Новый тап немедленно заменяет текущую
цель в любом состоянии — Walking, Holding, WAIT. Ошибочный тап исправляется
следующим тапом без штрафа.

**Specification**:
- Если за кадр пришло несколько press, побеждает последний (TR-control-018);
  эмулированное касание мыши отбрасывается.
- Путь считается один раз при принятии цели и не пересчитывается на ходу; тап
  по той же цели — новое принятие из текущей позиции.
- Прежний контур и кольцо (P6) снимаются в том же кадре.
- Отклонённый тап не прерывает текущий приказ (см. P1).
- После конца партии ввод в кухню отклоняется (TR-control-019).

**When to Use**: весь ввод в мир.
**When NOT to Use**: экранные кнопки (P4) — они не прерывают и не ставят в очередь игровой ввод.

**States**: N/A — правило обработки ввода, не видимый элемент; видимые состояния — у P6.

**Accessibility**: нет штрафа за лишний тап — снижает цену моторной ошибки.

**Implementation notes**: одна обработка на кадр в `TapInput` (ADR-0006).

### P4. Guarded Screen Button

**Category**: Input / Modal · **Used In**: Play Again, Share, Menu в оверлее итогов (P12)

**Description**: Экранная кнопка, которая не реагирует сразу после появления,
чтобы тап, начатый во время партии, не проскочил итоги и момент рекорда.
Активируется тапом, левым кликом или клавишами Enter/Space.

**Specification**:
- Цель касания ≥ 48 × 48 dp; видимая подпись.
- Оживает после fade-in оверлея (~250 мс) + `restart_input_grace_ms` (500 мс,
  данные HUD); тап или клавиша, нажатые раньше или удерживаемые с тех пор,
  игнорируются (HUD AC 51); автоповтор клавиши (echo) игнорируется.
- При появлении оверлея кнопка получает клавиатурный фокус — Enter/Space
  работают без предварительного Tab.
- Одна команда на нажатие: Play Again → `request_new_match()` (повторные нажатия до
  `match_started` игнорируются — очередь в `MatchLifecycle`, ADR-0003); Share →
  системное «Поделиться» (синхронно, `game-flow.md` M8); Menu → главное меню.
- Grace — общее окно для всех трёх кнопок; фокус — на Play Again. Визуально это
  кнопки P17 (primary / secondary / текстовая), активация — по release после grace.
- Время grace идёт от `ui_dt` — стоит, пока вкладка скрыта.

**When to Use**: любое необратимое действие на экране поверх замороженной сцены.
**When NOT to Use**: игровой ввод в кухне — там нельзя задерживать отклик (TR-control-015).

**States**:
- disabled (grace) — приглушена, без отклика на тап, клик и клавиши;
- default (enabled) — полная светлота, одиночное «вдыхание» масштаба при
  включении (при reduced motion — без анимации);
- hover (только мышь, enabled) — чуть светлее + курсор «рука»;
- focus — двухтонное кольцо как у P17 (Ink 3 dp + зазор 2 dp + ореол Parchment 2 dp),
  контраст ≥ 3:1 к фону, не красное и не зелёное, видно и в disabled (WCAG 2.4.7);
- pressed — утопление на 1 кадр → команда.

**Accessibility**: WCAG 2.1.1 (клавиатура) и 2.4.7 (видимый фокус) для этой кнопки;
подпись текстом, не только иконкой; цель ≥ 48 dp.

**Implementation notes**: активация — действие `ui_accept` (Enter/Space) на
кнопке с `focus_mode = FOCUS_ALL`; `grab_focus()` при показе оверлея —
в 4.6+ это клавиатурный фокус, отдельный от мышиного
(`docs/engine-reference/godot/modules/ui.md`, Dual focus). Grace держится
собственным флагом, а не `disabled = true`, чтобы фокус не терялся — проверить
на 4.7.2. Стиль фокуса — `focus` StyleBox, hover — `hover` StyleBox; курсор —
`mouse_default_cursor_shape = CURSOR_POINTING_HAND`.

### P5. Input Routing by Zone

**Category**: Input · **Used In**: экранные полосы HUD, letterbox, оверлеи итогов и паузы (с под-панелями), слой «Rotate your phone»

**Description**: Экран делится на кухню (`kitchen_rect`) и всё остальное. Тап
вне кухни никогда не превращается в движение баристы; при открытом оверлее
тапы и клавиши получает только оверлей.

**Specification**:
- Интерактивны только настоящие кнопки и открытый оверлей (`MOUSE_FILTER_STOP`).
  Кнопки P14 (пауза, звук) лежат выше слоя затемнения оверлеев P12/P15 и остаются
  живыми при них (кроме паузы в итогах — она приглушена).
- В мир ввод попадает через `_unhandled_input` узла `TapInput` (ADR-0006).
- Тап по полосе или letterbox — без реакции и без звука.
- **Исключение — P20.** Неинтерактивные плашки и слои поверх кухни (плашка «Till
  full!», попап NEW BEST!, виньетка последнего страйка) тапы **не** поглощают:
  тап сквозь них уходит в мир как обычно. Это единственный случай, когда UI лежит
  поверх `kitchen_rect` во время `Active` без модальности.
- Слой «Rotate your phone» поглощает весь ввод, включая кнопки HUD (лежит выше них).

**When to Use**: всегда — это правило маршрутизации, а не видимый элемент.
**When NOT to Use**: —

**States**: N/A — невидимое правило; курсор над полосами и letterbox — обычный.

**Accessibility**: тап мимо кухни ничего не стоит.

**Implementation notes**: все неинтерактивные `Control` (корни полос, подписи,
контейнеры) — `MOUSE_FILTER_IGNORE`, иначе полноэкранный корень проглотит тапы
по кухне (ADR-0002 §6).

### P6. Selected-Target Outline & Destination Ring

**Category**: Feedback · **Used In**: Player Control (для всех P1/P2)

**Description**: Мгновенное подтверждение «тап принят, иду туда».

**Specification**:
- Цель — станция или гость: подсветка контура выбранной цели **без смены
  оттенка** (оттенки заняты шагами); держится до прибытия или перенаправления.

**When NOT to Use**: отказ и экранные кнопки — у них свои сигналы (P9, P4).

**States**: N/A — неинтерактивная обратная связь; жизненный цикл: появился → держится → снят.

**Accessibility**: без оттенка; reduced motion — кольцо без пульса.

**Implementation notes**: `Sprite3D` с фиксированным поворотом к камере,
`no_depth_test`, альфа-смешивание (ADR-0002 §5). Никаких линий `CanvasItem`.

### P7. World Status Token

**Category**: Data Display · **Used In**: жетон заказа над гостем (шаги + цена), жетоны содержимого чашки, теги станций

**Description**: Компактная бирка над объектом, которая читается в движении и
всегда смотрит в камеру. Ряд жетонов шагов в порядке заварки плюс цена цифрой.

**Specification**:
- Каждый шаг — круглый жетон своего цвета с тёмным глифом; различим в оттенках
  серого и в трёх симуляциях дальтонизма (`order-recipe-system.md`).
- Жетон шага 20–24 dp (глиф читается при 16 dp) — это **размер отображения,
  не цель касания**: жетоны неинтерактивны. Цель касания гостя — pick-радиус
  28 dp вокруг якоря (P1, ADR-0006).
- Цена: цель ≥ 12 dp на экране при 9:20. Решено 2026-09-30 (hud.md E5,
  accessibility OQ 6): `Label3D` цены ×1,55 (≈ 7,7 → ≈ 12 dp), растут только
  цифры, бирка — минимально; цена остаётся над гостем; приёмка — retained
  screenshot на 9:20 с 4 гостями.
- Фон бирки — тёплый пергамент, цена — самый контрастный элемент.
- Гость в Approaching: масштаб и непрозрачность 0,7; в Waiting — 1,0 и поверх
  (TR-hud-013).
- Состояния чашки не оттенком: совпадает — галочка + тёплый блик; испорчена —
  крестик + обесцвеченный ряд.
- Бирка следует за объектом; при Served/Leaving снимается мгновенно.

**When to Use**: любая информация, привязанная к конкретному объекту в кухне.
**When NOT to Use**: сводные числа партии (счёт, страйки) — это экранная полоса (P10/P11).

**States**: N/A — неинтерактивна; hover/focus/pressed не существуют. Состояния
данных: Approaching / Waiting; чашка — собирается / совпадает / испорчена.

**Accessibility**: форма главная, цвет вспомогательный; контраст цены ≥ 4,5:1.

**Implementation notes**: слои мир < оверлеи Approaching < оверлеи Waiting <
жетоны чашки в руках (`render_priority`, альфа-смешивание,
`outline_render_priority` ниже основного; ADR-0002).

### P8. Radial Countdown Ring

**Category**: Data Display · **Used In**: терпение гостя

**Description**: Кольцо вокруг гостя, убывающее радиальным wipe'ом по
`remaining_fraction`, с тремя уровнями срочности, которые различаются
иконкой и ритмом, а не оттенком.

**Specification**:
- Нейтральный тон (кремово-белый/серый); длина дуги = `remaining_fraction`.
- Уровни calm / warn / urgent на порогах 0,60 / 0,25 (данные Guest AI):
  calm — без пульса; warn — медленный пульс + иконка «насторожен»; urgent —
  быстрый пульс ≤ 2 Гц + иконка + поза гостя «злость».
- Served — кольцо снимается мгновенно.
- Кольцо неинтерактивно; цель касания гостя — pick-радиус 28 dp (P1).

**When to Use**: убывающий ресурс времени, привязанный к объекту мира.
**When NOT to Use**: время партии целиком и загрузка — это не кольцо над объектом (P13 для загрузки).

**States**: N/A — неинтерактивно; состояния данных calm / warn / urgent.

**Accessibility**: без оттенка; reduced motion — нет пульсов, уровень передают
иконка и поза; не более 3 вспышек яркости в секунду даже при четырёх кольцах urgent.

**Implementation notes**: рисуется текстурой/регионом спрайта, никогда `draw_arc`
(ADR-0002); пульс от `sim_dt`, замирает на паузе.

### P9. Object State Glow

**Category**: Feedback · **Used In**: чайник (EMPTY / BREWING / READY), касса Open → Full, совпадение чашки с заказом, отказ станции

**Description**: Состояние показывается на самом предмете — корпусом,
заполнением, свечением, паром, — а не числом в полосе.

**Specification**:
- Чайник: EMPTY — матовый, без подсветки; BREWING — жидкость поднимается
  синхронно с таймером, тепло нарастает; READY — янтарное свечение крышки + пар
  (самый «громкий» статус).
- Касса: заполнение на предмете; переход в Full — одиночный акцент «потолок»,
  без числа в полосе (TR-hud-010).
- Совпадение чашки: подходящий тикет вспыхивает один раз, без постоянного пульса.
- Отказ станции (недопустимый шаг, Brewing AC-2.4): одиночная вспышка
  **светлотой** + глиф «крестик» на станции, старт ≤ 50 мс от тапа.
  Красный оттенок не используется — формулировку Brewing Rule 2 «мигает
  красным» нужно привести к правилу проекта (см. Gaps).

**When to Use**: состояние, которое принадлежит одному предмету.
**When NOT to Use**: сводные числа партии — P10/P11.

**States**: N/A — неинтерактивно; состояния данных перечислены выше.

**Accessibility**: звук дублирует, но не заменяет; reduced motion — одиночные
акценты остаются (это не цикл), пар — статичный кадр.

**Implementation notes**: все эффекты от `sim_dt`.

### P10. Popup Number

**Category**: Feedback · **Used In**: `+score_earned` (очки), `+coins_added` (монеты) и отскок излишка при полной кассе

**Description**: Короткое число, которое показывает полное значение сразу и
улетает к своему счётчику — «куда уходит заработанное».

**Specification**:
- Полное значение сразу, без счёта вверх; дуга ~400 мс (TR-hud-015).
- Три канала различия (не только цвет): очки — мятно-бирюзовый + звезда + дуга
  вверх к счётчику `match_score`; монеты — золото + монетка + дуга вниз к кассе.
- Излишек при полной кассе — отскок монетки без числа.
- Два события в одном кадре — со сдвигом ~100 мс (детали — в HUD-спеке).

**When to Use**: одноразовое начисление, которое уже отражено в постоянном счётчике.
**When NOT to Use**: уникальная информация — попап живёт ~400 мс и не должен быть
единственным её носителем.

**States**: N/A — неинтерактивно (`MOUSE_FILTER_IGNORE`).

**Accessibility**: дублирует видимые счётчики; reduced motion — число появляется у
цели и гаснет, без дуги.

**Implementation notes**: время — `sim_dt`; движение — offset-transform `Control`
(новое в 4.7: `offset_transform_*`, независимо от layout;
`docs/engine-reference/godot/modules/ui.md`, ADR-0002 Implementation Guidelines),
не `Tween`.

### P13. Boot & Failure Screens

**Category**: Loading / Error · **Used In**: HTML-оболочка (ADR-0001, ADR-0004)

**Description**: Всё, что игрок видит до готовности кухни или вместо неё, —
обычный HTML вне движка, поэтому оно работает, даже если движок не может
стартовать.

**Specification**:
- Загрузка: логотип + полоса прогресса + **одна подсказка** из списка (случайная
  на каждую загрузку — это не геймплей; список — `game-flow.md` M5), без жёсткого
  таймаута; переход к главному меню — CSS cross-fade без белой вспышки после
  `ready_reached`.
- Нет WebGL2: статичная страница «Please update your browser», движок не загружается.
- Ошибка конфига или навигации: статичный экран «Couldn't load the game — please
  refresh the page»; в debug-сборке — полный список ошибок.

**When to Use**: всё до `ready_reached` и все фатальные ошибки старта.
**When NOT to Use**: ошибки во время партии — их показывает игра, а не оболочка.

**States**: N/A — интерактивных элементов нет (обновление — средствами браузера).

**Accessibility**: обычный HTML — доступен экранным чтецам; при
`prefers-reduced-motion` cross-fade заменяется мгновенной сменой, блик полосы прогресса
не анимируется (CSS media query).

**Implementation notes**: CSS-анимация — оболочка вне движка; запрет
`Tween`/`Timer` (сквозные правила) её не касается, `sim_dt`/`ui_dt` здесь не существуют.

### P14. Icon Button (Toggle & Action)

**Category**: Input · **Used In**: пауза и «без звука» в полосе HUD (`hud.md` E3, E4)

**Description**: Компактная кнопка-иконка для редких служебных действий. Лежит
вне зоны игрового жеста, состояние читается по форме иконки.

**Specification**:
- Цель ≥ 48 × 48 dp; зазор между целями ≥ 8 dp; иконка контрастна ≥ 3:1 к фону полосы.
- Активация по **press** (единственный жест игры); release и drag игнорируются;
  повторные нажатия в тот же кадр схлопываются в одну команду. Grace-окна нет
  (действие обратимо; grace — у необратимого P4).
- Toggle («без звука»): применяет значение в том же кадре, меняет форму иконки
  (динамик с волнами / с диагональной чертой), пишет `settings.muted` в SaveStore
  при изменении (dirty flag, ADR-0005); плохой или отсутствующий ключ → `false`.
- Action («пауза»): отправляет команду в `MatchLifecycle` и меняет иконку на
  «воспроизвести» на время паузы; в `MatchEnd` приглушена, место остаётся.
- Лежит выше слоя затемнения оверлеев (P5): звук работает всегда.

**When to Use**: редкое обратимое служебное действие, не часть игрового жеста.
**When NOT to Use**: игровые действия (это P1–P3); необратимые (P4, P19); список
настроек — это P18; действия с текстовой подписью — P17. Кнопка Back (←) в
заголовке разделов меню — тоже P14 (иконка 48 dp), но срабатывает по release, как
кнопки меню.

**States**:
- default — диск Parchment 40 dp в цели 48 dp, глиф Ink (art-bible §7.4) — контраст не зависит от вечернего фона полосы;
- hover (только мышь) — чуть светлее + курсор «рука»; на тач-устройствах не показывается;
- focus — двухтонное кольцо как у P17 (Ink 3 dp + зазор 2 dp + ореол Parchment 2 dp), ≥ 3:1, не красное и не зелёное (WCAG 2.4.7); фокус ставится
  Tab, **мышиное нажатие клавиатурный фокус не берёт** (dual focus, 4.6+; проверить на 4.7.2);
- pressed — утопление на 1 кадр → действие;
- disabled — приглушена (пауза в `MatchEnd`); без отклика на тап, клик и клавиши; фокус виден.

**Accessibility**: форма, не цвет; цель 48 dp; клавиатура Tab + Enter/Space
(автоповтор игнорируется); состояние звука сохраняется между сессиями.

**Implementation notes**: `Button`/`TextureButton` с `focus_mode = FOCUS_ALL`,
`mouse_default_cursor_shape = CURSOR_POINTING_HAND`; значение звука применяется
к шине Master (SFX и музыка), поток музыки при этом продолжает идти беззвучно.
**Reference**: `design/ux/hud.md` E3, E4.

### P15. Pause Overlay

**Category**: Modal / Overlay · **Used In**: пауза по кнопке (`hud.md` E15)

**Description**: Игрок останавливает партию сам, без ухода со страницы.
Замораживает игровое время так же, как скрытая вкладка, но не снимается возвратом
вкладки.

**Specification**:
- Вход: кнопка паузы (P14) или Escape в `Active`. Команда идёт в `MatchLifecycle`
  («пауза по кнопке», ADR-0003) — единая механика паузы, HUD не пишет в `GameClock`.
- Вход также — поворот тач-устройства в ландшафт (`hud.md` E22): та же пользовательская пауза.
- Оверлей появляется в том же кадре, что и принятие команды (snap, без fade):
  затемнение (`pause_dim_alpha` 0,55) над кухней и панель «Paused» с кнопками P17:
  **Resume** (primary, фокус клавиатуры сразу на ней), **Settings**, **Main Menu**.
- **Settings** — панель настроек (P18) на месте панели паузы; **Main Menu** —
  диалог End shift? (P19). Escape / Back / Cancel на под-панели → панель паузы, пауза
  не снимается. End shift → `request_quit_match` → `match_ended(quit)` → меню.
- Выход: Resume, Enter или Space на ней, Escape на панели паузы или кнопка паузы
  («воспроизвести»). Обратного отсчёта нет — время идёт с первого кадра.
- Возврат вкладки (и возврат телефона в портрет) при паузе по кнопке **не** снимает паузу; скрытие вкладки без
  паузы по кнопке — автопауза без оверлея (как раньше). Время идёт, только когда
  сняты обе причины.
- Тапы и клавиши получает только оверлей (P5); кнопка звука остаётся живой.
- Недоступна в `MatchEnd` и до `match_started`; в кадре `match_ended` побеждает
  `match_ended`. Не влияет на счёт и рекорд.
- Музыка на паузе — пауза потока; возобновление с той же позиции.

**When to Use**: остановка партии по воле игрока.
**When NOT to Use**: конец партии (P12), скрытие вкладки (автопауза без оверлея).

**States**: сам оверлей — N/A (контейнер); интерактивные состояния — у кнопок P17
(без grace), переключателей P18, диалога P19 и кнопки паузы (P14). Все —
без анимаций состояний (`ui_dt = 0`).

**Accessibility**: закрывает WCAG 2.2.1 (доступная пауза); клавиатура без мыши;
заголовок ≥ 20 dp, кнопки — по P17, контраст ≥ 4,5:1; без вспышки.

**Implementation notes**: оверлей **статичен** — появляется и скрывается мгновенно,
без анимации: при пользовательской паузе `ui_dt = 0` (ADR-0003, Amendment
2026-09-30), эффекты в полёте замирают в фазе и продолжаются после Resume.
Отклик кнопок — только мгновенная смена состояния; под-панели заменяются мгновенно. Escape перехватывается
только в `Active` и `Paused`; автоповтор клавиш игнорируется.
**Reference**: `design/ux/hud.md` E3, E15, Dynamic Behaviors.

### P16. Simultaneous Feedback Stagger

**Category**: Feedback · **Used In**: импульсы ухода гостей и пульсы страйков (TR-hud-014)

**Description**: Когда несколько одноразовых сигналов одного типа наступают в
одном кадре, состояние применяется сразу, а старты их анимаций разносятся, чтобы
читались как отдельные события, а не один смазанный.

**Specification**:
- Состояние (жетон и кольцо снимаются, страйк гаснет) — **в кадре события**, без сдвига.
- Старты одноразовых пульсов — по очереди в порядке возрастания ID слота:
  `t_event + i × 100 мс` (`leaving_pulse_stagger_ms`); при трёх уходах 0 / 100 / 200 мс.
- Событие, пришедшее позже, ставится на `max(t_event, t_последнего_старта + 100 мс)`.
- Очередь ведётся в `sim_dt`; после `match_ended` (`sim_dt` = 0) доигрывается на `ui_dt`.
- Сдвиг сохраняется при reduced motion (он про читаемость, не про движение).
- Не теряет событий и не блокирует ввод. Попапы одной подачи сдвига не имеют (одна
  чашка — одно `Served` за кадр).

**When to Use**: ≥ 2 одноразовых сигнала одного типа в одном кадре.
**When NOT to Use**: разнотипные сигналы (награды, подтверждения ввода — независимы).

**States**: N/A — правило планирования, не видимый элемент.

**Accessibility**: разнесение снижает риск смазанного сигнала; суммарно не более
3 вспышек яркости в секунду.

**Implementation notes**: очередь в презентационном слое, стабильная сортировка по ID.
**Reference**: `design/ux/hud.md` E7, Очередь фидбека.

### P17. Menu Button

**Category**: Input · **Used In**: главное меню, How to Play, Records/Settings (Next, Start shift, Done, Skip), оверлей итогов (P12), панель паузы (P15), End shift? (P19) — `design/ux/game-flow.md`, `hud.md` E14/E15

**Description**: Обычная текстовая кнопка вне игрового темпа. Три веса —
primary, secondary и текстовая, — чтобы главное действие экрана было очевидно
без чтения.

**Specification**:
- **Primary**: ≥ 240 × 64 dp, текст 24 dp; одна на экран (Play, Next / Start shift /
  Done на карточках How to Play, Resume, Play Again). В P19 primary нет — обе кнопки
  secondary, действие отличается рамкой «опасное», фокус на Cancel.
- **Secondary**: ≥ 200 × 52 dp, текст 20 dp (Records, Settings, How to Play,
  Share, Main Menu, End shift, Cancel); вариант «строка» — Send feedback / About в Settings.
- **Текстовая**: подпись без рамки 18 dp, цель касания всё равно ≥ 48 dp по высоте и
  ≥ ширины подписи + 16 dp (Menu на итогах, Skip, ⊕ Install app, Not now).
- Зазор между кнопками ≥ 8 dp. Текст до ~14 символов на 24 dp; только английский (F3).
- **Активация по release** внутри кнопки: press вдавливает (темнее + сдвиг 2 dp),
  действие — на отпускание внутри; палец, соскользнувший за границу, отменяет
  нажатие. Клавиатура: Enter/Space на фокусе (срабатывает на нажатие, echo
  игнорируется).
- Одна команда на нажатие; повторные нажатия до завершения перехода игнорируются.
- **Фокус**: при показе экрана фокус на primary (в P19 — на безопасном варианте);
  ↑/↓ и Tab / Shift+Tab — по вертикальному порядку; видимое двухтонное кольцо (States).
- **Вид (art-bible §7.4)**:

  | Вес | Форма | Заливка / текст |
  |---|---|---|
  | Primary | пилюля ≥ 240×64, «губа» 4 dp снизу, контур Ink 2,5 dp | Mint Neon / Ink (≈ 7:1), Fredoka 24 dp |
  | Secondary | пилюля ≥ 200×52, губа 3 dp | Parchment / Ink, Fredoka 20 dp |
  | Текстовая | без рамки | Ink или Parchment по фону, Nunito 18 dp |
  | Опасная (End shift) | secondary с **двойной рамкой Ink** | не красная |
- Первое нажатие любой кнопки меню — «первый жест» для разблокировки аудио браузера.
- На итогах к P17 добавляется grace P4; на паузе — никаких анимаций (`ui_dt = 0`).

**When to Use**: любое действие с текстовой подписью вне кухни.
**When NOT to Use**: действия в полосе HUD во время партии (P14 — иконка, press);
игровой ввод (P1–P3).

**States**:
- default — полная светлота;
- hover (только мышь) — светлота +8 % + курсор «рука»;
- focus — **двухтонное кольцо: Ink 3 dp с зазором 2 dp от контура + внешний ореол
  Parchment 2 dp** — отличается от обычного контура Ink и без цвета, ≥ 3:1 и на
  пергаменте, и на скриме; Mint Neon и Gold для фокуса запрещены (WCAG 2.4.7);
  в Godot — `focus` StyleBoxFlat с `expand_margin`;
- pressed — губа схлопывается, сдвиг 2 dp вниз, темнее на 10 % (reduced motion — только темнее);
- disabled — заливка обесцвечена, текст альфа 0,45, губы нет (например, во время grace P4 или перехода); фокус виден.

**Accessibility**: подпись текстом; цель ≥ 48 dp; контраст текста ≥ 4,5:1 на
кнопке; арт-заставка не лежит под текстом без подложки; клавиатура без мыши.

**Implementation notes**: `Button` с `focus_mode = FOCUS_ALL`, `action_mode =
ACTION_MODE_BUTTON_RELEASE`, `mouse_default_cursor_shape = CURSOR_POINTING_HAND`;
строки через `tr()` с ключами с первого дня (`game-flow.md` Localization).
**Reference**: `design/ux/game-flow.md` Component Inventory, Interaction Map.

### P18. Toggle Row

**Category**: Input · **Used In**: Settings — Music, Sound effects, Vibration (из меню и из паузы)

**Description**: Строка настройки «подпись слева — состояние справа», где целью
касания служит вся строка.

**Specification**:
- Высота строки ≥ 56 dp, на всю ширину колонки; разделитель между строками.
- Состояние — **текстом ON / OFF** в капсуле справа (форма капсулы тоже меняется:
  заливка / контур); цвет вспомогательный.
- Тап / клик по любой точке строки (по release, как P17) или Enter/Space на
  фокусе → значение меняется **сразу**, без кнопки «Сохранить»; применяется к
  системе в том же кадре (шины Music / SFX, вибрация) и пишется в SaveStore
  (`settings.*_on`, dirty flag, ADR-0005).
- Короткий клик-звук при переключении, если Sound effects включены.
- Строка, которую платформа не поддерживает (Vibration без `navigator.vibrate`),
  **не показывается** вовсе — не серая.
- Плохой или отсутствующий ключ → значение по умолчанию (`true`).

**When to Use**: бинарная настройка, которая живёт между сессиями.
**When NOT to Use**: быстрое выключение звука посреди партии (P14 «без звука» в
полосе); выбор из списка (dropdown в MVP нет).

**States**:
- default — подпись + капсула ON или OFF;
- hover (только мышь) — строка чуть светлее + курсор «рука»;
- focus — двухтонное кольцо (как у P17) вокруг всей строки, ≥ 3:1;
- pressed — строка темнее на время нажатия;
- disabled — не используется (неподдерживаемая строка скрывается).

**Accessibility**: состояние текстом и формой, не цветом; вся строка — цель;
клавиатура; вибрация всегда дублируется визуальным сигналом.

**Implementation notes**: `Button` на всю строку с `toggle_mode = true` или
`CheckButton` с растянутой областью касания; на паузе — без анимации капсулы.
**Reference**: `design/ux/game-flow.md` Settings, Data Requirements.

### P19. Confirm Dialog

**Category**: Modal / Overlay · **Used In**: End shift? — выход из партии в меню из паузы (`hud.md` E15)

**Description**: Короткое подтверждение необратимого действия. Защищает от
случайного тапа на телефоне; по умолчанию ничего не ломает.

**Specification**:
- Панель на месте панели паузы: заголовок (вопрос, 22 dp), одна строка
  последствий (16 dp; «Your score and coins so far are kept.»), две кнопки P17 в ряд:
  действие (End shift) слева, отмена (Cancel) справа.
- **Фокус — на безопасном варианте** (Cancel); Enter сразу после открытия ничего
  не ломает.
- Escape или тап по затемнению вне панели = Cancel.
- Действие → одна команда (`request_quit_match`), повтор игнорируется.
- Поверх паузы — статичен (`ui_dt = 0`): появляется и скрывается мгновенно.

**When to Use**: действие, которое завершает партию или теряет прогресс.
**When NOT to Use**: обратимые действия (переключатели, навигация по меню) —

**States**: контейнер — N/A; кнопки — по P17 (default, hover, focus, pressed).

**Accessibility**: текст вопроса и последствий виден целиком; клавиатура; цели ≥ 48 dp;
фокус на безопасном варианте (WCAG 3.3.4 — предотвращение ошибок, по духу).

**Implementation notes**: панель внутри `CanvasLayer` оверлея паузы; модальность — P5.
**Reference**: `design/ux/game-flow.md` Confirm «End shift?»; `hud.md` E15.

### P20. Non-blocking Banner

**Category**: Feedback · **Used In**: плашка «Till full! Great day» (`hud.md` E19), попап NEW BEST! (E20), виньетка последнего страйка (E21), тост «Image saved, text copied» на итогах (фолбэк Share, `game-flow.md` M8)

**Description**: Сообщение о важном моменте, которое не останавливает игру и не
перехватывает ввод. Игрок может не смотреть на него — сигнал продублирован на
объекте, звуком или вибрацией.

**Specification**:
- **Неинтерактивна**: `MOUSE_FILTER_IGNORE` у плашки и всех её детей — тап
  сквозь неё уходит в мир (явное исключение из P5; только для этого паттерна).
- Лежит в `CanvasLayer` поверх кухни, но **не перекрывает** цены на жетонах и
  кольца терпения больше, чем на время показа; виньетка — только по периметру.
- Показ по событию; время показа — данные (Tuning Knobs `hud.md`): плашка ≈ 2 с,
  попап ≈ 1,2 с, тост ≈ 2 с; виньетка — до конца партии.
- Не более одной плашки каждого вида одновременно; повторное событие того же вида
  перезапускает показ, а не складывает плашки.
- Идёт в канале «награды» очереди фидбека; при совпадении стартов с другим
  одноразовым сигналом — сдвиг 100 мс (P16).
- Время: плашка и попап — `sim_dt` (замирают на паузе), виньетка — `ui_dt`;
  тост на итогах — `ui_dt`.

**When to Use**: момент, о котором стоит сказать посреди партии, но который не
требует ответа (праздник, предупреждение).
**When NOT to Use**: всё, что требует решения игрока (P12, P15, P19); постоянное
состояние предмета (P9 на самом предмете).

**States**: N/A — неинтерактивный элемент; видимые фазы — появление, показ, исчезновение.

**Accessibility**: сигнал всегда продублирован на объекте (касса P9, счёт E1,
страйки P11) и не несёт единственную информацию; вибрация и звук отключаемы;
не мигает (виньетка — мягкий пульс ~1 Гц по краям); при reduced motion — без
сдвига и масштаба, только появление и исчезновение.

**Implementation notes**: `PanelContainer` / `TextureRect` с
`mouse_filter = MOUSE_FILTER_IGNORE` рекурсивно — любой дочерний `Control` со
`STOP` сломает «тап насквозь»; проверять автотестом ввода (`hud.md` AC 27).
**Reference**: `design/ux/hud.md` E19–E21; `design/ux/game-flow.md` M2, M8, M11, M12.
