## Purpose & Player Need

Спек описывает всё, что игрок видит **между** партиями, и переходы между этими
экранами и партией. Задача потока — довести игрока до кухни за **один тап** из
меню (Pillar 1: хаос за стойкой — главное, меню не должно ему мешать), при этом
дать место тому, что делает игру продуктом, а не демкой: запомненные настройки,
понятное обучение, статистику, к которой хочется возвращаться (Achievers,
Pillar 4), и ответ на вопрос «что с моей кассой сегодня» (Pillar 3).

**Игрок приходит в меню, желая** как можно быстрее снова оказаться за стойкой —
и по дороге увидеть, сколько сегодня в кассе, какой у него рекорд и серия.
Всё остальное (настройки, обучение, статистика) — по запросу, не на пути.

Внутренности партии (HUD, мировые оверлеи) здесь не повторяются — они в `hud.md`.

## Player Context on Arrival

| Ситуация | Состояние игрока | Что ему нужно |
|---|---|---|
| Первый запуск по ссылке | Любопытство, ноль контекста, часто телефон одной рукой | Сразу понять, что это игра про чай и что нажать; не читать стену текста |
| Ежедневный возврат | Знает игру; пришёл «наполнить кассу» | Увидеть кассу и рекорд, нажать Play — всё |
| Между партиями (итоги) | Адреналин, «ещё раз» | Мгновенный перезапуск; выход в меню — вторичен |
| Касса полна | Дневная цель выполнена | Понять, что игра на рекорд всё ещё доступна, и когда новый день |

## Entry & Exit Points

| Экран | Вход | Выход |
|---|---|---|
| **Boot** | Открытие URL | `ready_reached` → Main Menu (CSS cross-fade, P13) |

| **Records** | Меню | Back → Main Menu |
| **Match** | Play; How to Play (первый запуск); Play Again | Пауза; `match_ended` → Results |
| **Pause** | Кнопка паузы / Escape в партии (`hud.md` E3, P15) | Resume → Match; Settings; Main Menu → Confirm |
| **Confirm «End shift?»** | Main Menu из паузы | End shift → партия завершается (см. States) → Main Menu; Cancel → Pause |
| **Results** | `match_ended(lost)` (при `quit` не показываются) | Play Again → Match; Menu → Main Menu; Share → системное меню / фолбэк, экран итогов остаётся. Все три — с grace P4. Escape игнорируется |

## Layout Specification

### Information Hierarchy

**Main Menu** (сверху вниз по важности):
1. **Play** — самая крупная, первая в фокусе, в зоне большого пальца.
2. Статус дня: касса `A / C` и рекорд — одна строка под логотипом **[A]**
   (концепт: «заполнение кассы видно всегда»; без этой строки меню врёт о том,
   зачем игрок пришёл).
3. Records / Settings / How to Play — вторичные, одного размера, ниже Play.
4. Логотип и арт-заставка — атмосфера, не информация.

**How to Play**: картинка → одна короткая фраза → индикатор страницы → кнопки.
**Records**: рекорд крупно → последние 5 смен → итоговые счётчики.
**Settings**: три переключателя одного веса.

### Layout Zones

Все экраны вне партии — портрет, 9:20…1:1 (решение «portrait only»). Контент
вписывается в центральную колонку шириной `min(экран − 32 dp, 420 dp)`; на
почти квадратных экранах поля по бокам заполняет фон **[A]**.

| Зона | Main Menu | Разделы (Records / Settings / How to Play) |
|---|---|---|
| Верх (~35 %) | Логотип + арт-заставка; строка «Till / Best» | Заголовок раздела + кнопка Back (←) слева, 48 dp |
| Центр | Кнопка Play | Содержимое раздела |
| Низ (~40 %, зона большого пальца) | Records / Settings / How to Play | Кнопки действий (Next / Start shift / Done) |

Отступ от краёв ≥ 16 dp; отступ снизу учитывает `env(safe-area-inset-bottom)`
браузера (не Telegram-инсеты — они отложены).

Верхние ~45 % — неоновая вывеска **TEA RUSH** (Mint Neon, леттеринг на базе Fredoka, «трубка» Parchment; glow — только high-тир, на low — запечённый спрайт-ореол) и бариста за стойкой в hero-позе с чашкой. При полной кассе строка статуса: `● Till 250/250 · New day in 4h 12m` **[A]**.
Серия жива, но касса сегодня не полна: `🔥 3 · fill the till to keep it` (M14).

## States & Variants

| Экран | Вариант | Отличие |
|---|---|---|
| Main Menu | День Open | Строка `Till A / C` |
| Main Menu | День Full | `Till C / C · New day in Hh Mm`; счётчик пересчитывается раз в минуту **[A]** |
| Main Menu | Первый запуск (`best_score` = 0, нет смен) | Строка статуса: `★ Best 0  ● Till 0/250` — без пустых прочерков |
| Main Menu | `SaveStore.persistent = false` | Внизу строка «Progress can't be saved in this browser» (14 dp — минимум экранного текста, accessibility) **[A]** |
| Main Menu | Касса Full, отсчёт дошёл до 0 при открытом меню | Меню вызывает `check_day_reset()` (Till Rule 6) → касса Open `0 / C`, строка обновляется без перезагрузки |
| Main Menu | Активный вызов (`challenge.target > 0`) | Строка `⚔ Beat your friend: N` |
| Main Menu | Серия жива (`displayed_streak > 0`), касса сегодня не полна | `🔥 N · fill the till to keep it`; серия 0 — значка нет |
| Main Menu | Установка доступна (`beforeinstallprompt` пойман) / уже установлено | Строка `⊕ Install app` / строки нет |
| Boot | Загрузка / нет WebGL2 / ошибка конфига | P13: логотип + прогресс + подсказка (M5) / статичные HTML-экраны ошибок |
| Play | `tutorial.seen = false` | Сначала How to Play (режим «из Play») |
| How to Play | Из Play / из меню | Последняя кнопка Start shift / Done |
| Settings | Вибрация не поддерживается (`navigator.vibrate` нет, напр. iOS Safari) | Строки Vibration нет вовсе (не серая) **[A]** |
| Settings | Из паузы | Панель над затемнённой замороженной кухней, не полноэкранная |
| Records | Ноль смен | Рекорд `0`, вместо списка «Play a shift to see it here», счётчики `0` |
| Records | Меньше 5 смен | Показывается столько, сколько есть |
| Records | `stats.recent` повреждён | Список пуст как при нуле смен; счётчики — свои значения (PlayerStats валидирует, player-stats Edge Cases) |
| Results | Share: нет `navigator.canShare({files})` / нет и clipboard / игрок закрыл системное меню / ошибка share | Скачивание PNG + копирование текста + тост P20 / только копирование текста + тост «Text copied» / ничего / тот же фолбэк, что при отсутствии API — ошибок игроку не показываем |
| Results | Карточка не успела отрендериться к нажатию (медленное устройство) | Share приглушена (disabled P17) до готовности карточки; тапа «в пустоту» нет |
| Settings | Send feedback: браузер заблокировал новую вкладку | Ничего не показываем; в той же вкладке ссылку **не** открываем (игра бы закрылась); строка остаётся, повтор возможен **[A]** |
| Pause → End shift | Выход из партии | Партия завершается как обычный `match_ended` с причиной `quit`: очки идут в рекорд и статистику, монеты уже в кассе (их и так начисляли по мере подачи). Экран итогов **пропускается** — сразу меню **[A]** |

Почему выход засчитывается **[A]**: очки только растут в течение партии, поэтому
засчитанный выход не даёт эксплойта, а незасчитанный наказывает игрока, которого
отвлекли. Требует правки GDD — см. Open Questions.

## Interaction Map

Ввод: тач, мышь, клавиатура (web). Геймпада нет.

| Действие | Тач / мышь | Клавиатура | Результат |
|---|---|---|---|
| Нажать кнопку | tap / click, срабатывает по **release** внутри кнопки (P17) | Enter / Space на фокусе | Действие кнопки |

### M2. Момент «касса полна» (F9)

### M3. Горизонтальная ориентация (F6)

- **Телефон/планшет** (`pointer: coarse`) и соотношение сторон шире 1:1 → полноэкранный слой поверх всего: иконка телефона со стрелкой поворота, **Rotate your phone**. Ввод в игру закрыт.
- В партии (`Active`) это выставляет **пользовательскую паузу** (как кнопка паузы). После возврата в портрет виден оверлей паузы, игрок сам жмёт Resume — как с возвратом вкладки (правило 3 паузы в `hud.md`) **[A]**.
- В меню/разделах/итогах — только слой, без побочных эффектов.
- **ПК** (`pointer: fine`): слой не показывается; портретная колонка по центру, по бокам фон (как сейчас).
- Слой — HTML-оболочка или Godot? Godot **[A]**: ему нужно выставить паузу; оболочка не знает о партии.

### M4. Адресная строка (F7)

Ничего не делаем. Правило «кухня ≥ 95 %» считается от **видимой области**
(вьюпорта), а не от физического экрана — адресная строка просто уменьшает
вьюпорт, раскладка ADR-0002 это уже переживает. Смягчение — PWA (M7).

### M5. Экран загрузки (расширение P13)

Логотип + полоса прогресса + **одна подсказка** из списка (случайная на каждую
загрузку, это не геймплей — случайность допустима) **[A]**. Подсказки (черновые):

- Harder drinks pay more — look at the price above the guest.
- Any guest with the same order will take your cup.
- Wrong step? Toss the cup in the trash and start again.
- Your till fills once a day. Score has no limit.
- The kettle keeps brewing while you do something else.

Остаётся HTML/CSS вне движка. Reduced motion — полоса без анимации блика.

**Вид (art-bible §7.6):** фон Ember Dusk #3A1E14; неоновая вывеска **TEA RUSH** в той же позиции и масштабе, что в меню — cross-fade к меню читается как «вывеска зажигается»; прогресс — пилюля 8 dp (дорожка Parchment 20 %, заливка Till Gold); подсказка — Nunito 16 dp, цвет Parchment (≈ 12,8:1); шрифты — те же файлы, что в игре, `font-display: block`, без шрифтового CDN; экраны ошибок — та же панель Parchment; PWA `theme_color` — Ember Dusk.

### M7. Установка на домашний экран (PWA)

- **Сборка**: встроенная опция Godot web-экспорта *Progressive Web App*: манифест, иконки 144/180/512, `display: standalone`, `orientation: portrait`, цвет темы из палитры. Офлайн-кэш — да, но с правилом обновления: новая версия сборки подхватывается при следующем запуске (ADR-0001 amendment, риск «устаревшая сборка» уже описан в ADR-0005 §3).
- **Android/Chrome**: перехватываем `beforeinstallprompt`. В меню под кнопками появляется строка **⊕ Install app** (только пока установка доступна). После 3-й сыгранной смены на итогах один раз — плашка «Install Tea Rush for fullscreen play» с кнопками Install / Not now.
- **iOS Safari**: программной установки нет — та же одноразовая плашка после 3-й смены, но с инструкцией «Tap Share ⤴ then Add to Home Screen».
- Уже установлено (`display-mode: standalone`) → ни строки, ни плашки.
- Плашка показывается **один раз** за всё время (ключ `ui.install_hint_shown`) **[A]**; строка в меню остаётся.

### M8. Шаринг результата (F8)

- **Кнопка Share** на итогах (M1).
- **Карточка** 1080 × 1350 PNG **[A]** (портрет, хорошо смотрится в чатах и сторис): логотип, `★ 4250`, **NEW RECORD!** (если был), `34 cups served`, «Can you beat me?», адрес игры.
- **Вид (art-bible §7.6, §7.7 п. 9, §8.6)**: плоская иллюстрация без 3D-рендера; фон Parchment с рамкой-слипом, поля 64 px; **всё ключевое — в центральном квадрате 1080×1080** (чаты обрезают превью до квадрата); логотип сверху (~15 % высоты); **★ 4250** — Fredoka, высота ≥ 20 % карточки; штамп NEW RECORD! с наклоном −6°; ключевой текст ≥ 48 px, контур ≥ 6 px; **только Ink на Parchment**, без мелкой фактуры; бариста — в углу, не под текстом. Проверка — в превью ~250 px.
- **Важно для реализации**: браузер разрешает «Поделиться» только прямо в обработчике нажатия. Поэтому карточка рендерится **заранее**, на `match_ended` (SubViewport → PNG → Blob в JS), а нажатие только вызывает `navigator.share({files, text, url})` синхронно.
- **Фолбэки**: нет `navigator.canShare({files})` (ПК-браузеры) → скачать PNG + скопировать текст «I scored 4250 in Tea Rush ☕ Can you beat me? <url>» в буфер, тост **Image saved, text copied**. Нет и этого → только копирование текста.
- Игрок закрыл меню «Поделиться» — ничего не происходит, без ошибок.

если партия `Active`. Не поддерживается — молча ничего. Настройки нет. **[A]**

### M11. «New best!» прямо в партии *(обязательно)*

- **Когда**: в кадре первого Served, после которого `match_score > best_score`
  (значение **на старте партии**, строго больше). Один раз за партию. При

- **Что**: попап **NEW BEST!** под плашкой счёта (E1), масштаб 1,3 → 1,0 за

- **Источник**: Currency — новое событие `record_passed` (однократно за партию).
  HUD сам не сравнивает (Core Rule 2 «HUD не хранит состояние»).
- Очередь фидбека: канал «награды», старт через 100 мс после попапа очков той же подачи (P16). Элемент `hud.md` E20.

### M12. Напряжение на последнем страйке *(обязательно)*

- **Когда**: `guests_lost == max_guests_lost − 1` (при 3 — после второго ушедшего
  гостя). Держится до `match_ended` (страйки не восстанавливаются).
- **Картинка**: затемняющая виньетка по краям кухни (альфа 0 → 0,35 за 400 мс),
  дальше медленная пульсация 0,25 ↔ 0,35 с частотой ~1 Гц. Цвет — тёмный тёплый,
  **не красный как код состояния** (правило accessibility: состояние читается
  по индикатору страйков E2 — последняя иконка ещё и пульсирует).
- **Звук**: музыка «сжимается» (ведущий слой уходит, low-pass 2500 Гц, −3 dB)
  и поверх включается тихий слой «сердцебиение» (fade-in 400 мс, 1 Гц).
  Темп и высоту музыки не меняем **[A]**: с pitch-сдвигом музыка «плывёт»
  (`audio-juice-feedback.md` Rule 7, решение владельца S1 2026-10-01).
- Не перекрывает жетоны и кольца терпения: виньетка только в крайних ~12 % по периметру.
- Пауза / скрытая вкладка — пульсация и слой замирают вместе с `ui_dt`.
- Reduced motion: статичная виньетка 0,3 без пульса; звук остаётся.

### M13. Вызов другу по ссылке

- **Ссылка**: карточка и текст шаринга (M8) ведут на `<url>/?beat=<score>` — счёт
  этой партии.
- **Приём**: при загрузке с `?beat=N` (целое, 1…1 000 000, иначе игнор) →
  сохраняется `challenge.target = N` (новая ссылка заменяет старый вызов), параметр
  убирается из адресной строки (`history.replaceState`), чтобы перезагрузка не
  повторяла вызов.
- **Меню**: строка под статусом — `⚔ Beat your friend: 4250`.
- **Итоги**: если `match_score > challenge.target` → строка **You beat your
  friend's 4250!** + стингер «рекорд»; вызов считается выполненным и из меню
  исчезает (`challenge.target = 0`). Иначе — строка `Friend's score: 4250`.
- В установленной PWA параметра нет (иконка открывает чистый URL) — вызов
  работает только при переходе по ссылке. Сервера нет, число не проверяется —
  это дружеский вызов, не лидерборд.

### M14. Серия дней

- **Что считаем**: подряд идущие игровые дни (границы — `daily_reset_time_utc`,
  как у кассы), в которые касса **заполнилась** (переход Open → Full).
- **Номер дня**: `till-day-cycle.md` Formula 5 (`day_index`), событие `day_filled(day_index)` (Till Rule 10).
- **Правила серии и показа** — `player-stats.md` Formula 1 (рост/обрыв на `day_filled`) и
  Formula 2 (`displayed_streak`: 0, если последний заполненный день раньше вчерашнего).
  Здесь не дублируются.
- **Меню**: рядом с кассой `🔥 3` (при 0 — не показывается). Если сегодня касса ещё
  не полна, а серия жива — подсказка `🔥 3 · fill the till to keep it` **[A]**.
- **Итоги**: при росте серии — строка `🔥 4-day streak!`.
- **Records**: `Current streak` и `Best streak` вместо одной строки `Days till filled`
  (`stats.days_filled` остаётся как «всего дней»).
- Честность: часы устройства можно перевести — в MVP это принимается (всё локально,
  как и касса); серверная проверка — Backend & Persistence.

|---|---|---|---|---|
| Меню, статус | `best_score` | Currency | при показе меню | `0` → «Best 0» |
| Меню, статус | `till_amount / till_capacity`, состояние дня | Till | при показе меню; после `check_day_reset()` | не бывает (A ∈ [0, C]) |
| Меню, статус | «New day in Hh Mm» | Till Formula 6 `time_to_reset` | раз в минуту, пока меню открыто | < 1 мин → «New day in <1m»; ≤ 0 → `check_day_reset()` |
| Меню, статус | `displayed_streak` | PlayerStats Formula 2 | при показе меню | 0 → значка нет |
| Меню | `challenge.target` | GameFlow | при показе меню | 0 → строки нет |
| Меню | установка доступна | PlatformBridge | событие `beforeinstallprompt` / `appinstalled` | нет API → строки нет |
| Records | `best_score`, `recent`, счётчики, `streak`, `best_streak` | Currency, PlayerStats | при открытии | пустое состояние (States) |
| Итоги | `match_score`, `is_new_record`, `match_coins_added`, `match_cups`, `streak_grew_this_match` | Currency, Till, PlayerStats | один раз на `match_ended` | см. `hud.md` E14 «Пусто / null» |
| Settings | значения переключателей | AudioDirector, Haptics | при открытии; мгновенно при переключении | плохой ключ → `true` |
| Settings / About | версия сборки | `ProjectSettings` `application/config/version` | при открытии | пусто → строки версии нет |
| Settings | `feedback_url` | `FlowConfig` (ADR-0004) | при открытии | пусто → строки Send feedback нет |

`settings.muted` (кнопка «звук» в HUD) остаётся и глушит всё поверх отдельных
переключателей: звучит канал, только если `muted = false` **и** его `*_on = true` **[A]**.

Сохранённые ключи Currency/Till GameFlow напрямую не читает — только геттеры
владельцев (ADR-0005 §1: scope видит только свой префикс).

## Accessibility

Tier Basic+ (`design/accessibility-requirements.md`):

- Все кнопки ≥ 48 dp по короткой стороне, между кнопками ≥ 8 dp.
- Текст ≥ 14 dp везде (минимум экранного текста, accessibility-requirements); заголовки ≥ 20 dp.
- Контраст текста ≥ 4,5:1 на фоне панели (≥ 3:1 для текста ≥ 24 dp); арт-заставка не лежит под текстом кнопок без подложки.
- Вся навигация доступна с клавиатуры; порядок фокуса — Interaction Map; видимый фокус — контур 3 dp ≥ 3:1, не только цвет.
- Цвет не несёт состояние: «опасная» End shift отличается рамкой и подписью, серия — числом и значком, NEW RECORD — текстом.
- Переключатели показывают состояние текстом ON / OFF, а не только цветом.
- `prefers-reduced-motion` и внутриигровой reduced motion — все переходы мгновенные (таблица выше).
- Вибрация всегда дублируется визуальным фидбеком и отключаема.
- Ни один экран не ограничен по времени, кроме grace-окна на итогах (защита от случайного тапа, не ограничение). Тосты и плашки (P20) не несут единственную информацию.
- Экранный чтец: меню — канвас Godot, не читается (Known Limitation в accessibility-requirements); HTML-экраны загрузки/ошибок читаются.

## Acceptance Criteria

1. Из свежего запуска (не первый раз) до начала партии — **1 тап** (Play).
2. При первом запуске Play показывает How to Play; после Start shift или Skip — партия; повторный Play сразу стартует партию.
3. How to Play открывается из меню в любой момент; Done возвращает в меню, `tutorial.seen` не сбрасывается.
4. Переключатели Music / Sound effects / Vibration применяются мгновенно и переживают перезагрузку страницы.
5. Строки Vibration нет в браузере без `navigator.vibrate`.
6. Settings из паузы не снимает паузу; Back возвращает на паузу, время партии за это время не шло.
7. End shift в паузе: `match_ended(quit)`, рекорд обновляется, если побит; статистика +1 смена; сразу меню, итоги не показываются.
8. Records показывает рекорд, до 5 последних смен (новые сверху), Shifts played, Cups served, Days till filled, Current streak, Best streak; при нуле смен — пустое состояние «Play a shift to see it here» без ошибок.
9. Строка статуса в меню совпадает с кассой в HUD; при Full показывает время до нового дня.
10. Escape ведёт «назад» на каждом экране; в меню ничего не делает.
11. Весь видимый текст — на английском.
12. Все экраны корректны на 9:20, 9:16 и 1:1 без обрезки и горизонтальной прокрутки (скриншоты в `production/qa/evidence/`).
13. Reduced motion: ни одного движения на переходах.
14. Итоги: счёт накручивается ≤ 0,8 с, тап показывает финал сразу; при не-рекорде видна строка «N to beat».
15. Касса полна посреди партии: плашка 2 с + звон, партия не останавливается, тап сквозь плашку доходит до станции.
16. Телефон в ландшафте: слой «Rotate your phone», партия на паузе; обратно в портрет — оверлей паузы, время стоит до Resume. На ПК слоя нет.
17. Загрузка показывает логотип, прогресс и одну подсказку.
18. Settings → About показывает версию и лицензии (включая Godot MIT).
19. Android Chrome: строка Install app в меню, одноразовая плашка после 3-й смены; в установленном приложении их нет. iOS: плашка с инструкцией.
20. Share на Android/iOS открывает системное меню с PNG-карточкой; на ПК — PNG скачан и текст в буфере.
21. Во время партии экран телефона не гаснет; на паузе и в меню — гаснет по системным правилам.
22. Settings → Send feedback открывает `feedback_url` в новой вкладке; при пустом конфиге строки нет.
23. NEW BEST! появляется ровно один раз в кадре, когда счёт впервые стал больше рекорда на старте партии; в самой первой партии (рекорд 0) — не появляется.
24. После второго ушедшего гостя (при лимите 3) — виньетка и сердцебиение до конца партии; на паузе замирают; reduced motion — без пульса.
25. Ссылка `?beat=4250`: в меню строка вызова; после партии со счётом > 4250 — «You beat your friend's 4250!», строка вызова исчезает; невалидный параметр игнорируется.
26. Серия: заполнение кассы в дни N и N+1 → 🔥 2; пропуск дня → показывается 0, следующее заполнение → 🔥 1.
27. **Производительность** (эталон — слабый Android из ADR-0007): меню интерактивно ≤ 100 мс после `ready_reached`; переход меню ↔ раздел завершается ≤ 250 мс; от нажатия Play до `match_started` ≤ 400 мс (с fade); нажатие Share вызывает системное меню ≤ 100 мс (карточка готова заранее).
28. Клавиатура: каждый экран проходится по порядку фокуса из Interaction Map без мыши; стартовый фокус совпадает с таблицей.
29. На итогах Play Again, Share и Menu не реагируют первые `restart_input_grace_ms` после появления.
30. How to Play, открытый из Play, закрытый через Back/Escape → при следующем Play обучение показывается снова; через Skip — не показывается.
31. Весь текст вне партии ≥ 14 dp и влезает в лимиты строк без обрезки на 360 dp ширины.
